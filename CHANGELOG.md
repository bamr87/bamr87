# Changelog

This changelog tracks the hub's **versioned public interface**: the reusable workflows member repos call by reference, and the checker they run. The interface, the tag scheme (`vX.Y.Z` plus a floating `vX`) and the meaning of each bump are defined in [`docs/WORKFLOW-VERSIONING.md`](docs/WORKFLOW-VERSIONING.md). Changes to the dash, the site, registries and generated data are not listed here.

The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). Keep exactly one `## [Unreleased]` heading.

### Changed

- `.gitattributes` `jev-main-only`: `CATALOG.md` and `docs/README.md` are regenerated and committed on `main` only, by `jev-number.yml` after every push; `drift-check.yml` fails a pull request that edits one (`python3 -m tools.jev generated guard`). Generated spans (PRD block, README `AUTO:projects`, `docs/DASH.md` CLI reference) are regenerated by the same job and their PR-side drift checks are advisory. `_data/fleet.yml` `jev.enabled: true` with `jev.auto_tiers: [tier0]`.
- `_data/fleet.yml` `budget.loops.monthly_usd`: $25 → $50, so the month can afford one $40 doctor attempt (`test_ai_budget.py` pairs the two).
- `_data/fleet.yml` gains `evolution.model: claude-opus-5-5`, the exact id the workflow's `--model opus` resolved to; `test_evolution.py` reads the hard rules from the spec's render and holds the workflow's literals to `fleet.yml`.
- `_data/roadmap.yml`: roadmap ids (`FF-NNNN`) are now assigned at merge. A new entry is a fragment `_data/roadmap.d/<slug>.yml` with `id: FF-NEW`, cited elsewhere as `FF-NEW:<slug>`; `python3 -m tools.jev number apply` numbers it on `main` and appends it, and `number lint` rejects a hand-picked `- id: FF-NNNN`.
- `fleet-verify.yml`: a repo whose `app:` block gives nothing to start or serve on a local URL now stops in seconds with a **Not verified** warning and job summary, and fails under `gate: true`. An app that is configured but fails to build or start now fails the job whatever `gate` says, because no scenario ran. Until now both cases waited out the readiness timeout and passed.
- `_data/fleet.yml` `harness_refinement.enabled: true` (the maintainer's yes, 2026-11-07), for the incident reflector; the JEV guards allow `gh pr create` only with `--draft` and `git worktree` only as `add --detach` or `remove`.
- `python-tests.yml`: the test shards run under `COVERAGE_CORE=sysmon` (Python 3.12's `sys.monitoring`) instead of coverage's default tracer. Same tests, same advisory coverage table; the console, pages and spec files ran 2.2 to 2.5 times slower under the old tracer, and the change is measured at about 40% less test time on the named shards, the hub's largest single use of Actions minutes.
- `templates/verify/` 0.2.0: the seeded `verify.yml` caller of `fleet-verify.yml` stops re-running a verdict it already has. A label other than `verify` now gets a concurrency group of its own and a skipped job, so it neither re-runs the pass nor cancels the run in flight (Dependabot's two labels started 3 runs per PR, the content agents' four started 5). The `push:` trigger is gone: 151 of 155 sampled pushes to a default branch were merges of a PR that had just been verified, and a dispatch still verifies the default branch. Every PR commit and the `verify` label run as before, and `gate` is unchanged. Over 14 days these runs were 469 of the fleet's 1,009 Verify runs and 946 of its 2,840 wall-clock minutes. `archive/` keeps the 0.1.0 shapes, so `tools/fanout.sh --kit verify --upgrade` moves the 23 untouched copies.
- `/dash-status` and `/evolve` are folded into `/harness:status` and `/loops:evolution` (its `hub` stage is the hub's own evolution chain).
- The harness surface check and the catalog read a `.claude/commands/` subdirectory as a namespace (`loops/scout.md` is `/loops:scout`).

### Fixed

- `.github/actions/claude-run`: installs `@anthropic-ai/claude-code@latest` explicitly. Claude Code now declares `engines: node>=22`, so on the fleet's Node 20 a bare package name made npm fall back to 2.1.197, which current models reject (`400 … version 2.1.280 or newer is required`); every `claude-run` step on Node 20 failed over to the API path. The CLI is a native binary and runs on any Node.
- `tools/dash up` checks the core `db` volume against its Postgres image and refuses to recreate onto an older major, naming the exact migration; the PG 15 → 18 bump had left the core database restarting in a loop on the first recreate.
- The core `db` healthcheck passes `-d` to `pg_isready`, so it no longer logs `FATAL: database "wikijs" does not exist` into the log plane every 10 seconds.
- `tools/pg-major-upgrade.sh` reads the cluster the image will open (`<major>/docker`, then the mount root) before searching, so a volume holding a second cluster cannot report the wrong major.
- `docker-compose.yml`, `docs/DOCKER.md` and `AGENTS.md` no longer point the core's migration at `dash dev db-upgrade hub`, which targets the separate `fleet-hub` volume.
- `tools/jev` loop runner (HUB-060): the per-run sandbox evidence works on Claude Code 2.1.308 — the sandbox runtime's per-command line is read from its stderr under `SRT_DEBUG` (which the agent environment now sets) and recorded by `ai-run` in the outcome file, the `--settings` read-fence line is required as well, and the live canary's judge no longer reads a traceback's echoed source as a network success, pairs each `cat` with a python twin, and plants neutrally named fixture files (bamr87/bamr87#560, decision 4c).
- `tools/jev` loop runner (HUB-060): the live canary appends the `cat` and `python3` probe grants a step's allowlist lacks (the doctor grants no `python3`), recorded in its verdict, so a narrower step's sandbox can be proven instead of judged inconclusive.
- JEV conflict resolution (`tools/jev/conflicts.py`): a tier-1/2 model attempt now runs with an explicit, narrow tool grant (read, edit, stage, read-only local git) under `--permission-mode dontAsk`, with no MCP servers, and is refused at $0 on a CLI older than 2.1.259; the run's permission denials are recorded in the ledger. Before this a headless attempt inherited the operator's own rules, every edit was denied, and it reported `success` with the conflict untouched.
- JEV conflict validation reads only the files the merge touched and counts a marker-shaped line only when neither parent has it, so a seven-`=` reStructuredText underline or an article that quotes a conflict no longer fails every resolution in that repository.
- `_data/token_rotation.yml`: an applied rotation now publishes each repo it wrote in its post-write condition (`state: ok`, `age_days: 0`, the write time), keeps what the survey saw as `observed_state` / `observed_age_days` / `observed_oldest_age_days`, and takes `counts` and `oldest_age_days` over the post-write rows; the harness scorecard, the `credential-overdue` wire and the `oauth-secret` coverage gap read an applied `action: written` row as present and fresh, so a credential the run just wrote no longer reads as missing or overdue.
- `claude-run` (and so `ai-lane.yml`): an empty `model:` in the consumer's `_data/ai.yml` resolves to the fleet default, as the kit's seeded file says it does. It used to reach the CLI as `--model ""`. `--model` and `AI_MODEL` still win, and a named model is used as before.

## [2.0.0] - 2026-10-14

`standard-ci.yml` stops ignoring failed dependency installs, which can turn a green caller red, so this is a major release. Callers pin `@v2`; `v1` keeps the lenient installs.

### Changed

- **Breaking:** `standard-ci.yml` fails the job when a dependency install fails, instead of masking it with `|| true` (#310). The project itself is installed only when it is installable (a `setup.py`, or a `pyproject.toml` with a `[project]`, `[build-system]` or `[tool.poetry]` table): editable first, then a regular install, and a failure of both fails the job. A `pyproject.toml` that holds only tool config is skipped with a notice.

### Added

- `standard-ci.yml`: docs-only skip. A new `changes` job (5-minute timeout) lists the files changed by the push or pull request; when every one matches `docs-paths`, the `ci` job is skipped (a skipped job satisfies a required check). New optional inputs: `skip-docs-only` (default `true`), `docs-paths` (default `**/*.md **/*.markdown docs/** LICENSE* .github/ISSUE_TEMPLATE/** .github/*.md`) and `timeout-minutes` (default `30`, the previous hard-coded value). The check fails open: an unknown base, a compare error or a 300+ file diff runs CI as before. (#354; part of the Actions waste reduction, Oct 14, #268, #348).
- `site-quality.yml`: a reusable site quality scan (Lighthouse CI, axe-core at 390 px and 1366 px, pa11y contrast) with `mode: build` (build the Jekyll site against a fresh theme resolved to a commit SHA, recorded in the job summary and report) and `mode: url` (scan live URLs). New interface, additive: inputs `mode`, `config`, `base-url`, `source`, `build-command`, `build-command-token` (default `false`: a custom build gets no token unless the caller opts in), `theme-cache` (default `false`), `expired-allowlist-level`, `gate`, `artifact-name`, `retention-days`, `hub-ref`, `node-version` (default 22), `ruby-version`; outputs `status`, `errors`, `warnings`, `theme-repo`, `theme-sha`, `report-artifact`. Every threshold comes from the caller's config (`templates/site-quality/site-quality.schema.json`, `schema: site-quality/v1`); the defaults only report, and a collector that crashes while its check is gated fails the run. Runtime pinned exactly in `.github/site-quality/` with a committed lockfile, installed with `npm ci --ignore-scripts` and kept current by a Dependabot npm entry (axe-core and @lhci/cli minor/major bumps excluded: those are reviewed and released by hand). `lighthouse.public_upload` is honoured only in public repos; private and internal repos keep Lighthouse reports in the run artifact. UPS-QA-40, UPS-QA-41 and UPS-REPO-07 carry the hub-only exception for this runtime, declared in `specs/QUALITY.contract.yml` and parsed by `tools/sanctioned_lockfiles.py`.
- The `site-quality` kit (`templates/site-quality/`, `tools/fanout.sh --kit site-quality`): a caller pinned `@v1`, a report-only config template, the JSON Schema, pass/fail fixture sites, and draft rows UPS-QA-60..63 (`rollout: warn`, contract `specs/QUALITY.contract.yml`).

## [1.0.0] - 2026-10-03

The first tagged baseline: the interface exactly as it stood on `main` when the tags were introduced, so existing `@main` callers can move to `@v1` with no behaviour change.

### Added

- `standard-ci.yml`: the one-job reusable CI gate, with inputs `node-version`, `python-version` and `ruby-version`, each resolved as caller input, then the calling repo's `vars.*`, then the built-in default.
- `fleet-conformance.yml`: the reusable UPS conformance gate, with inputs `kinds`, `tier`, `gate` (default `false`, advisory), `hub-ref` (default `main`) and `python-version`, and the `ups-conformance` report artifact.
- `tools/conformance.py` 0.1.0 and `_data/specs.yml` (UPS 1.0, status draft): the checker and rows `fleet-conformance.yml` runs.
