### Added

- **Loop switches in the console** (constitution § 17, HUB-057): the Harness Console's new **Switches** page (Harnesses → Switches, `/switches`) reads every `_data/fleet.yml` `switches.loops` record against its live repo variable — the effective state (the most restrictive level, then the variable and any code-level hold), the map's state and drift — one table per repo. A toggle per loop and **All on / All off** per repo open a dialog that needs a reason and previews the flip (each variable's current → new value and the exact fleet.yml diff, writing nothing); **Apply** runs the new `switches-apply` operation behind the confirm, which sets each variable on a repo the hub owns, reads it back, records the flip in the map, the fleet activity log and the audit, and leaves the map edit for the operator to commit. Also `GET /api/switches`, `POST /api/switches/preview`, `tools/dash switches [list|plan|apply]` and the MCP tools `switches_list`, `switch_preview` and (with write tools) `switch_apply`. No switch tool reads, prints or changes a secret.
- `_data/fleet.yml` `switches:` registers the content outlets: every bash-365/bash-365.com and bamr87/it-journey workflow that gates on a `vars.*_ENABLED` variable (27 records in the new groups `bash-365-loops` and `it-journey-loops`), read live on 2026-11-25, all on.
