### Fixed

- **The assistant kit's fan-out lands where the app is.** The first dry run across the fleet (2026-11-22) showed `tools/fanout.sh --kit assist` reading only the files at a repo's root: it seeded nothing in five of the nineteen page repos, whose app sits in a subfolder (gitorio, cv-pro, rewind-arcade, zer0-CMS, ocrmd), put the React adapter outside the app in law-ai and fredgar-ai, put ragio-ai's payload where its server does not look, and would have vendored a copy of the payload into each of the seven zer0-mistakes sites. The arm now takes a repo's platform from the planner (`tools/dash apps assist`, the registry's `frontend.framework`), finds the app's own folder, vendors nothing into a theme consumer (the theme carries the page bridge, ADR 0014 P1), and keeps the copy a repo already has wherever it was moved to, so a re-run never seeds a second one. `python3 -m fleetcore.assist family <repo>` is the one word the engine asks for. Tests: `tools/test_fanout_assist.py`, one layout per repo the dry run got wrong.
