# A loop page shows its agent step and offers Run locally only on a console — evidence

> **Feature:** `HUB-NEW:console-loop-run-op` (fragment `features/features.d/console-loop-run-op.yml`, P2 of epic #484, bamr87/bamr87#487) · **Scenario:** `verify/scenarios/loop-run.yml` · **Result:** **PASS** (2/2 viewports) · **Generated by:** `node verify/runner.mjs --only loop-run --base http://127.0.0.1:4020` against the public build (`CONSOLE_BASE=/ tools/console/build-pages.sh` into a scratch directory, served statically) on 2026-11-03, plus a hand-driven pass on a worktree console (below).

The JEV loop runner (`tools/dash loop run`, docs/JEV.md) as the console's `loop-run` op: every loop page lists the agent steps whose spec has a `local:` block and offers **Run locally (dry run)** beside **Dispatch in CI**; the op form takes the loop, the step, one target and `rehearse`; the job page renders the engine's run record as structured fields with the cost labelled as the estimate it is. The public build shows the step and no run button: running it needs a console.

## The public build (the scenario)

Every step passed at both viewports: the route answered 200, the agent-step card rendered, the page text carried `repo-scout/scout`, `API-equivalent (estimate)` and `Dispatch in CI`, no element with `data-testid="run-locally"` existed, and the page did not scroll sideways.
