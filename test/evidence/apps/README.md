# The app portal: every fleet frontend opened inside the Harness Console — evidence

> **Feature:** `HUB-NEW:app-portal` (fragment `features/features.d/app-portal.yml`, P0 of [ADR 0005](../../../docs/adr/0005-console-as-fleet-portal.md)) · **Scenario:** `verify/scenarios/apps.yml` · **Result:** **PASS** (2/2 viewports, 27 steps each) · **Generated by:** `node verify/runner.mjs --only apps --base http://127.0.0.1:5113` against the public build (`CONSOLE_BASE=/ tools/console/build-pages.sh` into a scratch directory, served statically), 2026-11-04

The console's **Apps** page lists every frontend the registry declares and opens one in a sandboxed frame at its live address or its local dev stack, at the page width or one of the verify kit's device sizes. The same launcher (`tools/fleetcore/apps.py`) feeds `/api/apps`, the public snapshot and `tools/dash apps`.

No console errors were recorded.

## What the pass found

1. **The console's own Content-Security-Policy refused every check and would have refused every frame** (`connect-src 'self'`, `frame-src` limited to the observability planes): 40 console errors on the first load. Fixed: both directives now name exactly the launcher's origins, held equal by `tools/console/test_console.py`.
2. **`bash-365.com` pointed at a redirector.** Header checks called it frameable; the browser refused it. Fixed in the registry, and `tools/dash apps check` now reports an address that moves to an origin no registry entry declares (`tools/test_frontend_registry.py`).
3. **A path could climb out of an app** on a shared origin (`../../etc` under `bamr87.github.io/gitorio/`). Fixed: a path must stay under the target's base address.
4. **Device presets were two pixels short** (a border inside the frame's box). Fixed: the framed page now receives the exact width and height.
5. **Not fixed here, one repo per PR:** gitorio does not render without storage access, and the zer0 theme (`halfmoon.js`, `background-customizer.js`) and MkDocs Material throw on `localStorage` in an isolated frame.

## Not covered

Chromium only. No real project stack was started, so a Django app's default `X-Frame-Options: DENY` on a local target (djangoerp, fredgar-ai, zer0-CMS) is expected but was not observed. The scenario does not frame a live site, because the verify kit keeps a scenario on 127.0.0.1; live framing is covered by the interactive pass above. Safari and Firefox treat requests from a public page to 127.0.0.1 differently from Chromium and were not tried.
