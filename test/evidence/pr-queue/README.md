# The PR queue lists every open pull request, filters it, selects rows and plans a bulk action — evidence

> **Feature:** `HUB-NEW:pr-queue` · **Scenario:** `verify/scenarios/pr-queue.yml` · **Result:** **PASS**, desktop and mobile · **Generated by:** `node verify/runner.mjs --only pr-queue` against the worktree's console on `http://127.0.0.1:4013` on 2026-11-15, plus a hand-run dry run of every bulk action through the same console ([`dry-runs.json`](dry-runs.json)).

The replayable scenario now checks the **public build**: `/prs` shows *Runs on a console* in place of the queue and no bulk action bar. CI's Verify serves only that build, so the console steps that produced the images below never passed there (two 60 s waits for `[data-bulk-bar]` on every run). The console run below is the hand-recorded part, like `refine` and `loop-run`.

The console was started from the worktree (`uvicorn app:app` on `127.0.0.1:4013`, `CONSOLE_AUTO_HEALTH=0`, its own `DASH_CONSOLE_JOBS`, `DASH_CONSOLE_GITHUB_WRITES=off`) and read live GitHub under this machine's `gh` login: 218 open pull requests of the hub and the registry repos, a fresh answer in 23.8 s for a cold detail read and well under a second from the cache. The header's `34 uncommitted` and `0 tokens` are artefacts of the worktree copy. Nothing was written to GitHub: the scenario stops at the plan, the dry runs ran without `apply`, and every apply sent without `confirm=true` was refused by the job API.

## The dry runs

[`dry-runs.json`](dry-runs.json) records one plan per action on two or three real pull requests (keys, head commits and the op or skip reason; no titles), each followed by the `prs-act` or `prs-agent` job without `apply` and the same job with `apply` but without the confirm:

| Action | Planned | Dry-run job | Apply without confirm |
| --- | --- | --- | --- |
| Mark ready | 3 to do (`gh pr ready …`) | still matches GitHub | 409, refused |
| Update branch | 0 to do: both `CLEAN`, not `BEHIND` | still matches | 409 |
| Re-run checks | 0 to do on the three false-red zer0-mistakes pull requests: their latest run of each workflow is a success once the superseded cancels are set aside | still matches | 409 |
| Next-action comment | 2 to do, each editing the existing `<!-- fleet:pr-triage -->` comment in place | still matches | 409 |
| Add `needs-amr` | 0 to do: the repo has no `needs-amr` label, and the queue does not create one | still matches | 409 |
| Agent (fix CI) | 3 to do, one `claude-sonnet-5-5` session each, 40 turns, $2, ceiling $6 API-equivalent (estimate); each flagged gated | still matches | 409 |
| Close | 2 planned, the action **off** (`pr_queue.close.enabled` is false) | still matches | 409 |
| Merge | 3 planned with `--merge --match-head-commit <sha>`, each warned as gated, the action **off** (`pr_queue.merge.enabled` is false) | still matches | 409 |

The refusals of an apply while the switch is off, under `DASH_CONSOLE_GITHUB_WRITES=off`, and of a plan whose head moved are proven by `tools/console/test_pr_queue.py` against an in-memory `gh`, not here: running them against live GitHub would mean sending an apply.

Raw data: [`report.json`](report.json).
