# Layout capture — evidence (feature `HUB-NEW:ux-layout-capture`)

> **Feature:** `HUB-NEW:ux-layout-capture` in `features/features.d/ux-layout-capture.yml` · **Tests:** `templates/ux-audit/tests/layout.test.mjs`, `tools/test_ux_layout.py` · **Generated by:** `tools/dash ux capture --repo lifehacker.dev --repo zer0-mistakes` (and `--role section`, with and without `--inject-css`), then `tools/dash ux compare` against the live sites on 2026-11-22 · **Verified by:** agent (Claude Code, local Chromium 1255 headless shell)

`dash ux` loads every page the registry's `ux.surfaces` names at 375, 768 and 1280px and writes, per page and width, a geometry snapshot (every visible box), a wireframe SVG drawn from it, and a screenshot, with the layout rules (L1–L6) the page broke. It caught the defects reported on lifehacker.dev/news/wire/ on 2026-11-14, which every existing gate passed: at 375px the page scores **65 (1 error, 4 warnings)** and **100** at 768 and 1280px. With the section-layout fix injected as CSS (`--inject-css`, a preview, not a shipped fix) it scores **100** at every width; `compare` reports all five rules fixed, none introduced, and the tablet and desktop captures **structurally identical with 0% pixel difference**, so the fix is phone-only. The theme's own section page (zer0-mistakes.com/news/development/) shows the same defects (L4 at 375px; L6 at 375 and 768px), so they belong to the theme, not to lifehacker.dev.

A false positive found while building this is fixed and pinned by a test: lifehacker.dev's home page first scored 85 at every width on L1, because Bootstrap rows outside a container overhang the viewport by 12px. The theme clips that overhang (`html { overflow-x: clip }`), so nobody can pan to it; L1 now reads the viewport's overflow instead of `scrollWidth`, and the fixture `tests/fixtures/overflow.html` holds both cases.

## Not covered

- Chromium only, light colour scheme, one phone width (375px). Other engines, dark mode and 320px reflow are not measured.
- Live pages at one moment: content changes daily, so these numbers describe 2026-11-22, not a baseline. Nothing here is committed as a baseline yet.
- The L-rule thresholds (55% for a squeezed label, 32px for an indent, 5 lines for a lead) are calibrated on three pages and two fixtures. They warn; nothing gates on them.
- The section fix is a CSS preview injected at capture time. The real fix belongs in the zer0-mistakes theme (`_layouts/section.html`) and is not part of this change.
- Only the first 2400px of each page is measured (`--max-height`).
