# GitHub Projects in the Harness Console — evidence

> **Feature:** `HUB-041` (`features/features.yml`, epic #468 P1, #470) · **Scenario:** `verify/scenarios/gh-projects.yml` · **Result:** **PASS** (6 images, two viewports, no horizontal scroll, no console errors) · **Generated by:** a playwright-core script driving headless Chromium against the worktree's console on `127.0.0.1:4187` (recorded fixtures) and the public build served on `127.0.0.1:4188`, on 2026-11-15.

Fleet → **GitHub Projects** (`/gh-projects`) reads Projects (v2) across every fleet owner through `GET /api/gh-projects` and `GET /api/gh-projects/{id}/items` (`tools/console/gh_projects.py`, docs/PROJECTS-FRAMEWORK.md § 3a): which owners the token can read and why the others cannot, a project picker, and one project's items as a table or as a board grouped by the project's Status options. It is read-only, and it is never part of the public snapshot.

## A running console, on recorded fixtures

The console was started from the worktree (`uvicorn` over `app:app` on `127.0.0.1:4187`, `CONSOLE_AUTO_HEALTH=0`, its own `DASH_CONSOLE_JOBS`, `PROJECTS_TOKEN` set to a placeholder that is not a token) with `gh_projects._http` replaced by recorded GraphQL answers, so nothing reached GitHub and no real token was involved. The fixtures cover each owner state the page has to show: `bamr87` readable with three projects (one closed), `year-of-ai` readable with one, `ai-world-view` refused for the `read:project` scope, `bash-365` readable with none, and `EissaLab` answered as `null` with a NOT_FOUND error. The Fleet project's twelve items are illustrative (the epic's six phases and six others, one a draft, two with no Status); they are not a live read of project #14.
