# The Sprints page — the live expedite-sprint record — evidence

> **Feature:** `HUB-085` (expedite sprints, constitution § 27.7, issue #691) · **Scenario:** `verify/scenarios/sprints.yml` · **Result:** **PASS** at two viewports, on the public build twice: as committed (no record yet, the empty state) and with the test fixture's two records · **Generated by:** `node verify/runner.mjs` against static builds of this branch on 2026-11-16.

Harnesses → **Sprints** (`/sprints`) renders every live record in `_data/sprints/` (`sprint/v1`, read through `/api/sprints` from `tools/sprint_record.py`, the same document the drift gate's check (r) lints). It shows the record chosen with `?sprint=<slug>` (the active one by default) in full, then every sprint in a table. It has no form, no input and no route that writes: a record changes only by a pull request.

## The empty state (the build as committed)

Built with `CONSOLE_BASE=/ SITE_URL=http://127.0.0.1:4391 OUT=<scratch>/site-empty tools/console/build-pages.sh`, served with `python3 -m http.server`, and run with `node verify/runner.mjs --base http://127.0.0.1:4391 --only sprints`: all nine steps passed at both viewports ([`report.json`](report.json)).
