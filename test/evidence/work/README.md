# The Work board shows every open item in the order the loops take it — evidence

> **Feature:** `HUB-028` · **Scenario:** `verify/scenarios/work.yml` · **Result:** **PASS** (2/2 viewports) · **Generated by:** `node verify/runner.mjs --only work` against the public build (`CONSOLE_BASE=/ tools/console/build-pages.sh`, served on `http://127.0.0.1:4020`) on 2026-10-28 · **Console pass:** Playwright MCP against a console from this branch (`CONSOLE_PORT=4012 tools/console/run.sh`), same day · **Verified by:** agent (Claude Code)

/work renders the issue pipeline's issues, every open PR and the roadmap specs on six lanes with the next run's picks marked, a Priorities view and a Throughput view of each loop's cap and drain time. The public build says reprioritising runs on a console and does not scroll sideways.

## The public build (the scenario)

Every step passed at both viewports: the route answered 200, the Triage lane rendered, the stat tiles and the "Runs on a console" banner were present, the Throughput tab rendered the loops and the per-repository table, and neither tab scrolls sideways. The published board carries 107 issues, 38 PRs and 20 roadmap specs and no spec or BACKLOG.md item, which are read from submodule checkouts. The page says so instead of showing empty lanes.
