## How the fixture and the two builds were made

1. Two checkouts: **before** is the merge base `751aa47` (main as the branch last merged it), **after** is this branch (`2da0016` plus the kind-badge fix below, committed just before this bundle). Their `_data/` is identical.
2. In each checkout, the script below ran `test_fleet_triage.py`'s offline bashcrawl fake through **that checkout's own** `fleet_triage.build_report()` at the fixture's clock, put the result in place of bashcrawl's `prs` and `workflows` in the committed `_data/fleet_triage.yml` (bashcrawl's real issues kept), and merged its inbox rows into the committed inbox in the generator's order. The before generator yields no link, so its snapshot is exactly what `main` would have shown that day.
3. Each checkout was built with `CONSOLE_BASE=/ SITE_URL=http://127.0.0.1:<port> OUT=<dir> tools/console/build-pages.sh` (before on :4630, after on :4631), served with `python3 -m http.server`, and `_data/fleet_triage.yml` was restored with `git checkout --` straight after.
4. The scenario visits the before build by absolute URL and the after build by `--base`, at 1280×800 and 390×844.

```python
# usage: python3 fixture.py <checkout> <this branch's .github/scripts/dash-gen/test_fleet_triage.py>
import importlib.util, sys, types
from pathlib import Path
import yaml

tree, test_file = Path(sys.argv[1]), Path(sys.argv[2])
sys.path.insert(0, str(tree / ".github/scripts/dash-gen"))
import fleet_triage  # the checkout's own generator
if not hasattr(fleet_triage, "FIX_PR_CAP"):  # the base generator has no link; only the test's default argument reads it
    fleet_triage.FIX_PR_CAP = 0
spec = importlib.util.spec_from_file_location("tft", test_file)
tft = importlib.util.module_from_spec(spec)
spec.loader.exec_module(tft)

fleet_triage.now_utc = lambda: tft.NOV2
repo = tft.bashcrawl()
gh = types.SimpleNamespace(get_repo=lambda nwo: repo)
project = {"name": "bashcrawl", "repo_url": f"https://github.com/{tft.NWO}", "branch": "main"}
rep = fleet_triage.build_report([project], gh, dict(fleet_triage.DEFAULT_THRESHOLDS), 8)

path = tree / "_data/fleet_triage.yml"
snap = yaml.safe_load(path.read_text())
row = next(r for r in snap["by_repo"] if r["name"] == "bashcrawl")
row["prs"], row["workflows"] = rep["by_repo"][0]["prs"], rep["by_repo"][0]["workflows"]
inbox = [i for i in snap["inbox"] if not (i["repo"] == "bashcrawl" and i["kind"] in ("pr", "workflow", "merge"))]
inbox += rep["inbox"]
inbox.sort(key=lambda x: (-x["priority"], -(x["age_days"] or 0)))
snap["inbox"] = inbox[: fleet_triage.INBOX_CAP]
if "fix_links" in rep:
    snap["fix_links"] = rep["fix_links"]
path.write_text(yaml.safe_dump(snap, sort_keys=False, allow_unicode=True, width=10_000))
```

## Found by this pass

- **Kind badges were cut short** ("m…", "wor…", and one letter on a phone). The kind column had no minimum, so a long `why` squeezed it, and a merge row's why is the longest. It was already true for `workflow` on `main` at 1280 and for every kind at 390. The fix is the commit before this bundle: each kind badge in `InboxTable` (`tools/console/web/src/pages/ProjectPage.tsx`, shared by the Inbox and a project's page) has `miw="max-content"`, so it never shrinks below its word. The `kind_badges_whole` check holds it.
- **A merge row is tall on a phone.** Its why text wraps in the narrow why column, which sits off to the right until the table is scrolled. Nothing overflows the page. It is left as it is.
