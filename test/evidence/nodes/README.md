# The Nodes page shows where hub workloads run, and the published page says it probed nothing — evidence

> **Feature:** `HUB-068` · **Scenario:** `verify/scenarios/nodes.yml` · **Result:** **PASS** (2/2 viewports, 17 steps each, no console errors) · **Generated by:** `node verify/runner.mjs --only nodes` against the public build (`CONSOLE_BASE=/ tools/console/build-pages.sh`, served at `http://127.0.0.1:4605`) on 2026-11-16 · **Console pass:** Playwright against a console from this branch (uvicorn on `127.0.0.1:4606`, `CONSOLE_AUTO_HEALTH=0`), same day · **Verified by:** agent (Claude Code, local run)

`/nodes` has a card per node from `_data/fleet.yml` `nodes:`: the Mac as the edge, and forge as a workload node that is off. Each card shows the node's role, on/off state, reachability, capacity and the hub services placed on it. The placement table and the drift follow. The document is `fleetcore.nodes.status_doc`, which `tools/dash node status --json` prints and the MCP's `fleet_nodes` returns. The page writes nothing.

## The public build (the scenario)

Every step passed at both viewports:

- the route answered 200, and the placement table rendered;
- a banner says the published page probed nothing, so reachability, measured capacity and running containers come from a console;
- forge shows as off, with the capacity fleet.yml declares and the services it takes once it is enabled;
- drift reads "not read" rather than a zero that was never measured;
- the Overview carries the same line, which reads "placement drift: read on a console";
- no page scrolls sideways at 1280 or at 390.
