# Console pages as windows on the bashOS desktop — evidence

> **Feature:** `HUB-079` (phase D1 of [ADR 0005](../../../docs/adr/0005-console-as-fleet-portal.md)) · **Scenario:** `verify/scenarios/desktop-pages.yml` · **Result:** **PASS** (1/1 viewport, 15 steps) · **Generated by:** `node verify/runner.mjs --only desktop-pages --base http://127.0.0.1:5113` against the public build (`CONSOLE_BASE=/ tools/console/build-pages.sh` into a scratch directory, served statically), 2026-11-05

On the Desktop the console's own pages open as windows. The page inside is the same page without its header and sidebar, because the window is its frame.

## The public build (the scenario)

Every step passed: the **Console** icon opened a window holding the Overview page; inside the frame the page had rendered its heading (`framed_page: "Overview"`) with no header and no sidebar of its own; the address stayed `/desktop`; the taskbar's **bashOS** button opened its menu and **Roadmap** opened in a second window (`second_page: "/roadmap/"`); nothing scrolled sideways. No console errors were recorded. The scenario runs at desktop width only: at a phone's width there is no taskbar and the Console icon leaves for the classic console.

## A running console (the interactive pass)

Driven with Playwright against a console started from this branch's worktree on `127.0.0.1:4012` (its own virtualenv and job directory; the shared core on `:4001` was not touched).

| Image | What it shows |

Measured in that pass, not pictured:

- **Plain chrome.** The framed Overview page had no `header` and no sidebar; its frame carries no sandbox, because it is this app on this origin.
- **The window follows the page.** A link inside the Overview window went to `/projects`; the title became `Projects · /projects` and the tab's saved layout recorded that path. After a reload the windows came back on the pages they were on.
- **Open or focus.** Picking **Jobs** in the start menu a second time focused the Jobs window instead of opening another.
- **The palette.** With the Desktop on screen, `⌘K`, "Inbox", Enter opened an Inbox window; the address stayed `/desktop`.
- **Theme.** Toggling the theme on the desktop switched the pages inside all three windows.
- **A crafted layout.** A `?windows=` link naming the desktop itself, an external URL, `//host`, `/api/state` and `/../etc` as pages opened none of them; `/jobs` and `/projects/kvlite?tab=work` in the same link opened.
- **Forged route messages.** A message with an external URL for a path, and one that did not come from a window's frame, changed no window.
- **No nesting.** `/desktop` loaded in a frame shows "The desktop does not open inside one of its own windows."
- **The policy.** The console sends `frame-ancestors 'self'`.
