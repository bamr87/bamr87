# Home page renders with the dash navigation — evidence

> **Feature:** `HUB-001` · **Scenario:** `verify/scenarios/home.yml` · **Result:** **FAIL** (0/2 viewports, 6 steps each) · **Generated by:** `tools/dash verify --only home` against `http://127.0.0.1:4000` on 2026-09-05 · **Verified by:** agent (Claude Code, local run — `verified:` stamped in `features/features.yml` when passing)

A visitor lands on the profile/dash root, sees the main content, and can reach the Command Center pages from the sidebar without any sideways scrolling.

**FAIL — horizontal overflow on both viewports.** `scrollWidth` 1292 px vs a 1280 px viewport on desktop and 402 px vs 390 px on mobile: the page can be scrolled sideways, which means some element (the hero stat-card grid in the mobile capture, where the right-hand cards are clipped) is wider than its container. This is the class of defect zer0-mistakes' navbar fix (PR #215) measured with the same overflow metric; the fix belongs in the theme or the hub's `index.md` hero, not in this scenario. Every other assertion (HTTP 200, `main` landmark, no console errors) passed.
