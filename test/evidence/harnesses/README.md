# Harness inventory grades every AI workflow against the standard — evidence

> **Feature:** `HUB-005` · **Scenario:** `verify/scenarios/harnesses.yml` · **Result:** **PASS** (2/2 viewports, 28 steps each) · **Generated by:** `node verify/runner.mjs --only harnesses` against the static build served at `http://127.0.0.1:4321` on 2026-11-11 · **Verified by:** agent (Claude Code, local run)

The `/harnesses` page lists every AI workflow in the fleet from `_data/harness_registry.yml`: its route to a model, its caps and its verdict against the harness standard. Above the table, the rebuild plan groups the harnesses that fall short by the lever that fixes them; below it, the standard's controls each show how many harnesses miss them. The Repos view keeps the per-repo baseline and the kit deploy.

Every step passed at both viewports: each route answered 200, the plan, the tiles and the controls rendered, clicking a lever put it in the address and filtered the table, the `kind` filter listed the hub's scheduled loops, and no view scrolled sideways. This proves the page renders and filters at desktop and mobile widths from the committed data. It does not prove the verdicts are right: that is `test_harness_registry.py`.
