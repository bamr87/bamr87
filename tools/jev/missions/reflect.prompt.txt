# THE ADOPTED CANDIDATE IS NOT THE ONLY EVIDENCE

Selection compared deliverables with the harnesses hidden, so the choice

as evidence. An edit that appeared only in a rejected candidate may still

# WHAT EACH EDIT DID

Diff every candidate harness against `context/base_harness/`. For each
component any candidate changed, write one row: the component, what the
edit actually changed, the observed difference in execution it produced,
and a verdict. Verdicts are `helped`, `hurt`, `no observed effect` and
`confounded`. Use `confounded`, and prefer it, whenever a candidate changed
several components at once and no rollout isolates one of them, or when a
single rollout is all that stands behind the difference. A confounded row
is a useful record; an invented attribution poisons the library for every
later task. Cite the rollout and the point in the trajectory where
behaviour diverges.
