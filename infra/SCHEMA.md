# SCHEMA — infra

> OpenTofu root modules for the fleet's infrastructure as code: what outlives a container (ADR 0003, docs/PLATFORM.md).

## Conventions

- One directory per root module; every root module is initialised and validated by `.github/workflows/infra.yml`. `gcp/` groups its root modules one level down (`gcp/foundation/`, `gcp/node/`), and `infra.yml` validates those too.
- `azure/` is the exception: Bicep, not OpenTofu, because the fleet's Azure deployments are Bicep; `infra.yml` builds it with `az bicep` and skips it in the OpenTofu loop.
- Inputs are generated by `tools/dash node gen` / `dash infra plan` into `.fleet/nodes/`; state lives in `nodes.infra.state_dir`, outside the tree.
- Provider and version constraints are floors (`>=`), never ceilings; no `.terraform.lock.hcl` is committed.

## Structure

| entry | kind | purpose | rules |
| --- | --- | --- | --- |
| `README.md` | file | What this layer owns, how to plan and apply it, and how to adopt existing resources | required |
| `node/` | dir | Root module for one fleet node: its `fleet` Docker network and the volumes of the services placed on it | required |
| `azure/` | dir | Bicep deployments for the fleet's Azure resources (the bash-365 portal); compiled and linted by `infra.yml`, deployed by the maintainer | required |
| `gcp/` | dir | OpenTofu root modules for the platform on Google Cloud (ADR 0020): the landing zone and the machine the platform runs on, each read from `_data/hosting.yml`; validated by `infra.yml`, planned and applied by the maintainer with `gcp/deploy.sh` | required |

## Placement

- New kind of infrastructure (a cluster, a registry, DNS) → a new root module directory here, with its own `SCHEMA.md`, validated by `infra.yml`.
- New Azure resources → a deployment under `azure/` (its `SCHEMA.md` says how).
- New Google Cloud resources → a root module under `gcp/` (its `SCHEMA.md` says how), reading `_data/hosting.yml`.
- Anything unrouted → propose an entry in this table first, then create it.

## Forbidden

- No state, plan or lock file (`*.tfstate*`, `*.tfplan`, `.terraform/`, `.terraform.lock.hcl`).
- No secret values — a module takes a credential by variable from the environment, never a literal.
- No hand-written `*.tfvars` — the inputs are generated from `_data/fleet.yml`, or read by the module itself from `_data/hosting.yml` (`gcp/`); what must stay out of the repo comes from the environment.
