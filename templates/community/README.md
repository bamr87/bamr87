# Community kit

The fleet's community-health files: the ONE pull-request template carrying the fleet Definition of Done, the issue forms, the label taxonomy as a file, CODEOWNERS, Dependabot, CONTRIBUTING, SECURITY and the Code of Conduct. It closes the `community` kit gap in [`specs/CONFORMANCE.md`](../../specs/CONFORMANCE.md) and seeds UPS-REPO-14/15/16/18/19, UPS-QA-41, UPS-AGENT-32 and UPS-WORK-03/09.

**Inheritance first.** GitHub applies the community-health files of an owner's `.github` repository to every repo that has no copy of its own. So the default distribution is: these files become the defaults in `bamr87/.github`, `year-of-ai/.github` and `ai-world-view/.github`, and a repo only carries its own copy when it needs to ADD something. Updating those three repos is a Fleet Ops change; this kit is the source they copy from. CODEOWNERS and `dependabot.yml` are not inherited by GitHub, so they are copied per repo (the soft CODEOWNERS in `.github/templates/CODEOWNERS-soft.template` stays the fan-out source for UPS-REPO-16 until fan-out is wired to this kit).

**Decisions baked in.** The backlog of record is GitHub Issues with the fleet labels (D1); a file backlog is declared in `.github/sdlc.yml`. Agent instructions live in `AGENTS.md`, and `CLAUDE.md` is a pointer to it (D4). Every repo, content repos included, keeps a `CHANGELOG.md` generated by release-please from the Conventional-Commit PR titles, never by hand (D5).

## Contract (for conformance checks)

These are the facts a conformance check can lint. `test_community_kit.py` enforces them on the kit itself.

1. **Definition of Done.** A repo's effective PR template (its own, or the inherited default) contains the block between `<!-- fleet-dod:start v1 -->` and `<!-- fleet-dod:end -->`, and every `- [ ] **…**` box inside it is the kit's, in order. An override may add boxes BELOW the end marker, never inside it. A new DoD version bumps the marker to `v2`.
2. **Labels.** The names in `labels.yml` (families `state`, `type`, `priority`, `size`) equal `_data/fleet.yml` `issue_pipeline.labels`; `_data/fleet.yml` stays authoritative and the test fails on any disagreement. `renames:` lists GitHub defaults or legacy names (`enhancement`, `documentation`, `priority:Px`) that the sync job renames rather than duplicates. The `optional` family is created only when `.github/sdlc.yml` opts in.
3. **Issue forms.** Each form applies exactly one fleet type label plus `agent:queued`, and only labels from `labels.yml`. `config.yml` turns blank issues off and carries no per-repo URLs, so it is safe to inherit.
4. **SECURITY.md** has the headings `Supported versions`, `Reporting a vulnerability` and `Response window`, and states the 7-day window.
5. **Dependabot** covers `github-actions` weekly, grouped, with the `ci` commit prefix. Repos add their own ecosystems below it.

## Using it in a repo

- Do nothing: the inherited defaults apply once Fleet Ops updates the owner `.github` repo.
- Need extra gates? Copy `.github/pull_request_template.md`, keep the DoD block byte-identical, and add your items under `<!-- fleet-dod:end -->`. Do the same for `CONTRIBUTING.md` (add sections, keep the fleet ones).
- Copy `.github/CODEOWNERS` and `.github/dependabot.yml`, then add your package ecosystems to `dependabot.yml`.

## Changing the kit

1. Copy any file you are about to change into `archive/` as `<name>-<old version>.<ext>` (see [`archive/README.md`](archive/README.md)).
2. Edit, bump `VERSION` (`version`, `updated`, `changelog`), and run `python3 templates/community/test_community_kit.py`.
3. A label change starts in `_data/fleet.yml`; then mirror it in `labels.yml` (the test enforces the match).
4. Changing a DoD box changes every repo's PR template: bump the marker to the next `vN` and say so in the changelog.
