# SCHEMA — _data

> The dash's registries: single-source-of-truth YAML read by the public site (the console's page and its snapshot), dash-gen, the gates, and the evolution loop.

## Structure

| entry | kind | purpose | rules |
|---|---|---|---|
| `profile.yml` | file | WHO the public site is about — name, title, links, avatar, the site's own title and description (hand-edited; read by `tools/console/site_docs.py`; replaced the identity block of the retired Jekyll `_config.yml`) | required |
| `portfolio.yml` | file | HOW the profile README groups the portfolio — group headings, repo → group map, display-only extras (hand-edited; read by `.github/scripts/dash-gen` `readme`) | required |
| `projects.yml` | file | THE project registry — cross-checked against .gitmodules by the drift gate | required |
| `fleet.yml` | file | Central control-plane config: toolchain versions, cadences, remediation caps, the token contract, canonical repo variables, the `switches:` loop kill-switch map of constitution § 17 (validated by `tools/test_loop_switches.py`) (read by `tools/fleet-config.py`, `fleet-pulse.yml`, `remediation.py`) | required |
| `backlog_fanout.yml` | file | Backlog fan-out config — cadence (daily/weekly), the `apply` switch for scheduled runs (false = dry run), PR cap, skip labels, requirement → repo map (read by `tools/backlog_fanout.py`; docs/BACKLOG-FANOUT.md) | |
| `deep-dive.yml` | file | Daily repo deep-dive ledger — cycle start, 42-day rotation of every non-archived bamr87 repo with per-repo status, last run, issues/PRs, findings, score, next focus and optional Quest Log showcase (edited by `tools/deep_dive.py`; docs/DEEP-DIVE.md, docs/SHOWCASE.md) | |
| `deep_dive.json` | file | Frontend projection of `deep-dive.yml` with the cycle summary, read by `/deep-dive` (generated by `tools/deep_dive.py`; `json --check` gates staleness) | generated |
| `stars.json` | file | The open-source radar (`stars/v1`): the account's public GitHub stars with category, health, star velocity and closest fleet projects, the trending searches, each fleet project's matches, the review list and the feed; read by `/stars`, `fleet_stars` and the SessionStart brief (generated by `tools/stargazer.py refresh`, daily by stargazer.yml) | generated |
| `stars_ai.json` | file | The radar's AI pass (`stars-ai/v1`): one review per repo (summary, kind, verdict adopt · borrow · watch · skip, the fleet project it serves, why, ideas, model, date, input hash), the themes over the stars, and the last 50 sessions with their API-equivalent cost; laid over `stars.json` by every build (written by `tools/dash stars review --yes`, `local:stars-review`) | generated |
| `stars_history.json` | file | The radar's star counts (`stars-history/v1`): one a day for 10 days, then one a week for 13 weeks, per repo on the radar — what the velocities are measured from (written with `stars.json`) | generated |
| `jev_resolutions.yml` | file | JEV's conflict-resolution ledger (`jev-resolutions/v1`) — one append-only row per triage/resolution attempt (repo, PR, tier, model, outcome, cost and whether that cost was reported or estimated); the monthly `budget.jev` cap is judged on it (written by `tools/jev/conflicts.py`, published by jev-conflicts.yml; docs/JEV.md) | generated |
| `ports.yml` | file | THE fleet port allocation — bands, shared services, and every project's published ports (devenv-hosted ones on the workspace bands, with their `start:` command); projected onto the dev stack by `tools/fleet-compose.py`, gated by drift check (m), and read by the app portal for each frontend's local address (`tools/fleetcore/apps.py`) | required |
| `smoke.yml` | file | Recorded observation of every local fleet container — state, health, image, and per-service HTTP/TCP/postgres/redis/exec probes, plus the stable subset `dash dev smoke check` asserts (written by `tools/fleet_smoke.py record`) | generated |
| `docker.yml` | file | Consolidated Docker view for `/docker/` — every allocation joined to its live state, image, version-contract drift, attach point and harmonization status (generated by `tools/docker_view.py --write`; local-first, like the smoke recording it reads) | generated |
| `standards.yml` | file | Standardization tier baselines consumed by `dash audit` | required |
| `health_thresholds.yml` | file | Thresholds for the monitor board's attention signals | |
| `actions_usage.yml` | file | Actions usage snapshot for the analytics pages | |
| `ai_activity.yml` | file | Local Claude session data (gitignored; local-only view, written by dash-gen ai) | generated |
| `project_health.yml` | file | Ephemeral live-signal snapshot (gitignored; written by dash-gen health, never committed) | generated |
| `project_health_meta.yml` | file | Ephemeral metadata for the health snapshot (gitignored) | generated |
| `ai_usage.yml` | file | Committed fleet Claude Code usage ledger for /ai-usage/ (generated by fleet-pulse.yml) | generated |
| `fleet_triage.yml` | file | Committed daily fleet open-state snapshot (issues/PRs/CI) for /triage/ (generated by fleet-pulse.yml) | generated |
| `api_keys.yml` | file | Committed Anthropic API key ledger — per Console workspace, the key `dash keys rotate` deployed (id, name, expiry), when, and to which repos, plus the keys it retired (generated by `tools/fleet-config.py keys rotate --apply`; read daily by api-keys.yml). Key ids and dates only; never a value | generated |
| `token_rotation.yml` | file | Committed weekly credential-rotation ledger — per-repo secret AGES and outcomes for the fleet's Claude/CI tokens, plus the canonical repo variables and their values (generated by `tools/fleet-config.py rotate`, published by token-rotation.yml). Names and timestamps only; never a value | generated |
| `issue_pipeline.yml` | file | Committed three-tier issue-pipeline state (stages, queues, caps, taxonomy, every open issue under `backlog:` and every pipeline PR) for /issue-pipeline/ and the Work board (generated by issue-pipeline.yml) | generated |
| `harness_health.yml` | file | Committed six-layer harness scorecard + trip wires computed offline from the other fleet signals (generated by `dash-gen harness`, refreshed by fleet-pulse.yml; thresholds in fleet.yml `harness:` — see docs/HARNESS.md) | generated |
| `harness_registry.yml` | file | Committed fleet AI-harness + schedule inventory for /harnesses/ — every workflow that reaches a model, by any route, with its verdict against the harness standard and the lever that rebuilds it; per-repo baseline coverage, crons, throughput vs caps, cost trends/forecast, and the fan-out gap list (generated by `dash-gen harnesses`, refreshed by fleet-pulse.yml; contract in fleet.yml `harnesses:` — see docs/HARNESS-OPS.md) | generated |
| `agents.yml` | file | Committed agent inventory under the agentic efficacy contract (constitution § 29): every CI agent step, JEV loop step, conflict tier and LaunchAgent with its owner, trigger, switch, cap, model, KPIs, sources and contract gaps (generated by `dash-gen agents` / `tools/dash agents`, refreshed by fleet-pulse.yml, gated by drift check (p); contract in fleet.yml `harness.efficacy` / `sources` / `agents` — see docs/AGENT-EFFICACY.md) | generated |
| `voices/` | dir | THE fleet voice model `voices/v1` — `voices.yml` (canonical voices, styles, personas, topics and assignment per site; lifehacker.dev's SDLC cast) and `voices.schema.json`. Admin-edited by PR; the console editor writes back here (constitution § 23 rule 7). Validate with `tools/voices.py check` | |
| `editorial.yml` | file | THE editorial plan for the content atlas — per content site: narrative, audience, voice, pillars (match rules + target share of new work) and directives (decisions: proposed → approved → filed → done / rejected). Human-owned; the Console's Content tab and `dash content plan` edit it in the working tree with comments preserved (docs/CONTENT-ATLAS.md) | |
| `engagements.yml` | file | Engagement ledger for /engagements/ — per-client estimates, plans, actuals, variance (managed by `dash estimate`/`dash ledger`; humans own status/plan/broker_hours) | |
| `engagement_rates.yml` | file | Hand-edited rate card for engagement estimation (broker rate, tiers, contingency) | |
| `cv_portfolio.json` | file | Committed registry→CV projection (CVData Project/Skill shapes) consumed by the bamr87/cv sync loop (written by `dash-gen cv`; adopters merge it into that repo's data/cv.json) | generated |
| `roadmap.yml` | file | Feature roadmap entries surfaced on the dash; the Work board edits an entry's `status:` / `priority:` line in place; new entries are compiled in from `roadmap.d/` at merge (never a hand-picked `FF-NNNN`) | |
| `roadmap.d/` | dir | Pending roadmap entries, one `id: FF-NEW` fragment per file, numbered and compiled into `roadmap.yml` on `main` by `tools/jev/number.py` | |
| `agent_roles.yml` | file | Actor split for constitution § 26 — Claude Code executors vs Grok bot directors; path allowlist for direction-setting PRs; GitHub login warn list (names only) | |
| `mcp_servers.yml` | file | Hub MCP server lifecycle registry (`mcp-servers/v1`) — id, owner, transport, entrypoint, health, secret *names*, status, and `server_json` (the MCP Registry manifest, § 16.4); constitution § 25 / docs/MCP-SERVERS.md | |
| `work_queue.yml` | file | The human's order and priority overrides (`work-queue/v1`) — written by the console's Work board, read by the issue pipeline and repo-evolution (docs/WORK-BOARD.md) | |
| `sprints/` | dir | The live expedite-sprint records (constitution § 27.7): one `sprint/v1` state document per sprint — appetite, the three gates with who and when, phase, items, spend against the cap (API-equivalent (estimate)), trip wires, a DORA snapshot and the retro. Changed only by a reviewed pull request; linted by `tools/sprint_record.py` (drift check (q)) and rendered at `/sprints` (docs/EXPEDITE-SPRINTS.md); see its SCHEMA and README | |
| `harness_library/` | dir | The harness experience library — per loop and registry category, one entry per adopted refinement (`experience.yml`, `jev-experience/v1`, plus `harness.diff`), written on a branch by `tools/jev refine library add` and reviewed before `main`; read by the context pack's `library` provider and `refine evidence` (docs/HARNESS-REFINEMENT.md); see its SCHEMA | |
| `projects_backfill.yml` | file | THE reviewed triage + Fleet-board backfill plan (`projects-backfill/v1`) — per open hub issue: close (completed / not planned), label edits, sub-issue links, each with its evidence; the board rules on top of `templates/projects/framework.yml`; `applied:` records appended by the tool. Hand-edited; committing a change is the review; applied through the § 11 service by `tools/projects_backfill.py` (`dash projects plan` / `apply`; docs/PROJECTS-FRAMEWORK.md § 3b) | |
| `weekly_plan.yml` | file | The weekly routine's public record (`weekly-plan/v1`, tools/weekly/): the week's recap, the workspace's state in counts, the backlog, the plan and 12 weeks of history; written by the weekly PR, never by hand | generated |
| `pm_review.yml` | file | The routine PM review's public snapshot (`pm-review/v1`): Fleet project coverage, findings per lane, the planned project ops and roadmap edits, the release train and a 30-run history; private repos counted, never listed (generated by `tools/pm_review.py review --write`, published by fleet-pm.yml; docs/PM.md) | generated |
| `scripts.yml` | file | Catalog of fleet scripts | |
| `skills.yml` | file | Catalog of Claude skills across the fleet | |
| `templates.yml` | file | Catalog of seedable template kits | |
| `features_index.yml` | file | THE FLEET FEATURES INDEX — every repo's `features/features.yml` aggregated with verification coverage (tests / scenarios / evidence / screenshots / verified stamps graded from files on disk), per-repo gaps, and a ranked attention list; rendered at /features/ (generated by `tools/features_index.py fleet --write`, refreshed weekly by fleet-snapshots.yml from real submodule checkouts; docs/VERIFICATION.md) | generated |
| `conformance.yml` | file | Fleet UPS conformance snapshot — per-repo kinds, tier, pass counts, failing MUST/SHOULD rows (generated by `tools/conformance.py fleet --write`, refreshed weekly by fleet-snapshots.yml; read by `dash-gen targets` for the repo-evolution brief); its last key, `security:`, is the OpenSSF Scorecard block `tools/scorecard_snapshot.py --write` renders and `fleet --write` carries over | generated |
| `scorecard.yml` | file | Raw OpenSSF Scorecard results per registry repo (details dropped), the cache the `security:` block of `conformance.yml` is rendered from; written by the weekly `scorecard-sweep.yml` (`tools/scorecard_snapshot.py ingest`), absent until its first run (docs/SECURITY-POSTURE.md) | generated |
| `references.yml` | file | Hand-edited map of reference implementations in the fleet (repo + path) to the UPS requirement ids they exemplify; rendered into CATALOG.md | |
| `specs.yml` | file | The Universal Project Standard, machine-readable — every UPS requirement with level/applies/seed (generated by `tools/gen-specs-data.py` from `specs/*.md`; `--check` gates staleness) | generated |
| `architecture.yml` | file | The hub's structure contract (`architecture/v1`, ADR 0016): the line and size limits, the code layers in order, the upward imports allowed today with a `why` each, and the ledger of files held past a limit (hand-edited above the `ledger:` key; the ledger block is rewritten by `tools/architecture.py ledger --write`, which only lowers it; checked by `tools/test_architecture.py` on every PR) | required |
| `literal_owners.yml` | file | The literal owners the framework's code still carries (`literal-owners/v1`, ADR 0011 decision 2): the directories held, the generator counted only, the `allow:` rules for the framework's own address, the `enforce:` switch (false: report only) and the per-file baseline (hand-edited above the `baseline:` key; the block is rewritten by `tools/literal_owners.py baseline --write`, which only lowers it; `tools/test_literal_owners.py` holds `enforce` false until a reviewed change turns the gate on) | required |
| `checks.yml` | file | Which check a change owes (`checks/v1`): each existing gate or test with the path patterns that owe it, its command and what it needs installed (hand-edited; read by `tools/focus.py`; `tools/test_focus.py` holds every command to a tool that exists) | required |

## Placement

- New registry file → here, one `.yml` per concern, registered above.

## Forbidden

- No secrets or tokens — registries are public site data.

## Machine API (not a registry file)

Agent JSON is **not** stored under `_data/`. `dash-gen machine-api` projects the registries above into `_site/api/v1/*.json` (+ `llms.txt`) at Pages build time. See [`docs/MACHINE-API.md`](../docs/MACHINE-API.md).
