# SCHEMA — _data

> The dash's registries: single-source-of-truth YAML read by the Jekyll site, dash-gen, the gates, and the evolution loop.

## Structure

| entry | kind | purpose | rules |
|---|---|---|---|
| `projects.yml` | file | THE project registry — cross-checked against .gitmodules by the drift gate | required |
| `fleet.yml` | file | Central control-plane config: toolchain versions, cadences, remediation caps, the token contract, canonical repo variables (read by `tools/fleet-config.py`, `fleet-pulse.yml`, `remediation.py`) | required |
| `standards.yml` | file | Standardization tier baselines consumed by `dash audit` | required |
| `health_thresholds.yml` | file | Thresholds for the monitor board's attention signals | |
| `actions_usage.yml` | file | Actions usage snapshot for the analytics pages | |
| `ai_activity.yml` | file | Local Claude session data (gitignored; local-only view, written by dash-gen ai) | generated |
| `project_health.yml` | file | Ephemeral live-signal snapshot (gitignored; written by dash-gen health, never committed) | generated |
| `project_health_meta.yml` | file | Ephemeral metadata for the health snapshot (gitignored) | generated |
| `ai_usage.yml` | file | Committed fleet Claude Code usage ledger for /ai-usage/ (generated by fleet-pulse.yml) | generated |
| `fleet_triage.yml` | file | Committed daily fleet open-state snapshot (issues/PRs/CI) for /triage/ (generated by fleet-pulse.yml) | generated |
| `token_rotation.yml` | file | Committed weekly credential-rotation ledger — per-repo secret AGES and outcomes for the fleet's Claude/CI tokens, plus the canonical repo variables and their values (generated by `tools/fleet-config.py rotate`, published by token-rotation.yml). Names and timestamps only; never a value | generated |
| `issue_pipeline.yml` | file | Committed three-tier issue-pipeline state (stages, queues, caps, taxonomy) for /issue-pipeline/ (generated by issue-pipeline.yml) | generated |
| `harness_health.yml` | file | Committed six-layer harness scorecard + trip wires computed offline from the other fleet signals (generated by `dash-gen harness`, refreshed by fleet-pulse.yml; thresholds in fleet.yml `harness:` — see docs/HARNESS.md) | generated |
| `engagements.yml` | file | Engagement ledger for /engagements/ — per-client estimates, plans, actuals, variance (managed by `dash estimate`/`dash ledger`; humans own status/plan/broker_hours) | |
| `engagement_rates.yml` | file | Hand-edited rate card for engagement estimation (broker rate, tiers, contingency) | |
| `cv_portfolio.json` | file | Committed registry→CV projection (CVData Project/Skill shapes) consumed by the bamr87/cv sync loop (written by `dash-gen cv`; adopters merge it into that repo's data/cv.json) | generated |
| `roadmap.yml` | file | Feature roadmap entries surfaced on the dash | |
| `scripts.yml` | file | Catalog of fleet scripts | |
| `skills.yml` | file | Catalog of Claude skills across the fleet | |
| `templates.yml` | file | Catalog of seedable template kits | |
| `conformance.yml` | file | Fleet UPS conformance snapshot — per-repo kinds, tier, pass counts, failing MUST/SHOULD rows (generated by `tools/conformance.py fleet --write`; read by `dash-gen targets` for the repo-evolution brief) | generated |
| `references.yml` | file | Hand-edited map of reference implementations in the fleet (repo + path) to the UPS requirement ids they exemplify; rendered into CATALOG.md | |
| `specs.yml` | file | The Universal Project Standard, machine-readable — every UPS requirement with level/applies/seed (generated by `tools/gen-specs-data.py` from `specs/*.md`; `--check` gates staleness) | generated |
| `navigation/` | dir | Jekyll navigation data | terminal |

## Placement

- New registry file → here, one `.yml` per concern, registered above.

## Forbidden

- No secrets or tokens — registries are public site data.
